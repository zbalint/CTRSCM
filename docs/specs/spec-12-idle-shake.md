## 1. Why

The prompt cache has a 1 hour TTL on the owner's account. After a longer idle gap the cache is cold, so the next request writes the whole prefix to the cache at the write price (2x base input against 0.1x for a read, the ratios `hooks/report.ts` already assumes). A normal Shake guards against paying a cache rebuild for a small gain (`minSavings`), but on a cold cache the rebuild happens anyway, so that guard only throws savings away: with the owner's `minSavings` 100000 a 200k context holding 80k of shakeable tool output is left alone, and the first message back writes all 200k. A smaller prefix also makes every later read cheaper.

The design: remember when the last main-thread turn ended; on the **first prompt-box edit** (`prompt.edit`, the person typing or pasting) after a gap of at least `idleShakeMinutes` with no turn running, request one Shake with `minSavings` 0 before the person submits. The session is idle then, the Shake runs while they are still typing, and the first request back writes a smaller prefix. Everything else about a Shake (artifact first, placeholders, fallback = transcript untouched for a request) is unchanged.

**Verified, and why revisions 1 to 3 changed.**
- Revision 1 (`prompt.submit` hook): the `claude` binary (2.1.295) refuses `$.session.compact` called from `prompt.submit`, `tool.call`, `command.run`, `prompt.section` and the other events in its refusal list (`called from a prompt.submit hook, it would compact under the turn this hook is holding; call it from a later event (turn.complete)`). The mock reproduces it (`m_812`).
- Revision 2/3 (timer): an architect probe in the mock (scratch plugin outside the repo, 2026-10-08) shows a `$.session.compact` called from a `$.clock.after` callback is **not** run through the mod's own `session.compact` hook (calls from the `session.measure`, `turn.complete` and `prompt.edit` hooks do run it). In the real host the call would then reach core, i.e. the built-in summarizing compaction, at an idle moment. That is unsafe, so no timer.
- Revision 4 (`prompt.edit` hook): the refusal list in the binary does not contain `prompt.edit`; the same probe shows the compact resolves from a `prompt.edit` hook and runs the mod's own `session.compact` hook with the marked `instructions`.

**Still not known (live).** Whether the real host runs a marked compact from a `prompt.edit` hook exactly as the mock does, and whether a typed key during a running turn is distinguishable (it is gated by D3's turn flag). The call is **safe either way** (a rejection or any error leaves the transcript untouched, D4) and the option ships **off by default** (D1); the architect arranges a live probe after acceptance and flips the default only if it passes.

## 2. Decisions

- **D1. Option `idleShakeMinutes`**, default **0** (off), a safe integer at least 0; added to `Config`, `DEFAULT_CONFIG`, `CONFIG_OPTION_NAMES` and the `numericOption` name union in `hooks/config.ts`, with the same problem text as `adviseTokens`: `option idleShakeMinutes: must be a safe integer at least 0; using the default`. The owner enables it in `~/.ctrscm/config.json`. Reason for off: the host behavior in "What is not known" is unverified.
- **D2. A third request kind.** In `hooks/trigger.ts`: `Request = 'proactive' | 'aggressive' | 'idle'`, an exported `IDLE_MARK = 'ctrscm:idle'`, and `markOf` / `requestOf` handle it. `markOf` is a two-way ternary today (`hooks/trigger.ts:9`); make it a total mapping for three kinds (a `Record<Request, string>` lookup is fine; keep `PROACTIVE_MARK` and `AGGRESSIVE_MARK` exported with their current values). `decideRequest` and `decideAdvice` do not change.
- **D3. State.** In `register()` add `let lastTurnAt: number | undefined` and `let isTurnRunning = false`. A new `on('turn.start', ($, e, next) => { isTurnRunning = true; return next(e) })`. In the existing `turn.complete` hook: when `e.agentId === undefined` set `isTurnRunning = false` (before `await next(e)` returns is fine; place it first so a throwing `next` does not leave it stuck), and after `const result = await next(e)`, when `e.reason === 'answer' && e.agentId === undefined`, set `lastTurnAt = await $.clock.now()` inside a `try`; on a throw log `CTRSCM: idle clock failed: {message}` through `$.ui.log` and set `lastTurnAt = undefined`. A subagent's turn, an interrupted or errored turn does not move `lastTurnAt`. A fresh registration (new process, `/resume`) has `lastTurnAt` undefined and never idle-shakes: **known gap**, backlog B28.
- **D4. A `prompt.edit` hook**, `on('prompt.edit', async ($, e, next) => ...)`, that uses `$.` members directly (D9). Every gate must hold, otherwise it does nothing and ends with `return next(e)`:
  1. `config.idleShakeMinutes > 0` and `config.autoShake`; `e.origin.kind === 'composer'`.
  2. `!isTurnRunning`, `isRecoverReady`, `!isRequesting`, `!isPending`, `wanted === undefined` (a queued `/shake` or a retry already owns the next pass).
  3. `lastTurnAt !== undefined`, and `lastContext.tokens !== null && lastContext.tokens >= IDLE_MIN_CONTEXT_TOKENS`, a module constant `30000` in `hooks/register.ts` with a `// shortcut:` comment (fixed floor so a tiny session is never touched; make it an option if the owner wants it tuned). The floor is a separate gate, not a savings threshold: `minSavings` stays 0 inside the pass.
  4. `(await $.clock.now()) - lastTurnAt >= config.idleShakeMinutes * 60000`.

  When the gates hold: set `isRequesting = true` and `lastTurnAt = undefined` (one attempt per idle gap); `$.ui.log('CTRSCM: idle shake requested (idle {m} min)')` with `m` the configured `idleShakeMinutes`; then `await $.session.compact({ instructions: markOf('idle') })` in a `try`. On a throw: `$.ui.log('CTRSCM: idle shake rejected: {message}')`, `stats.last = 'idle skipped: compaction failed'`, and write a **failed** usage event (outcome `failed`, label `idle`, reason `compaction failed`: the same event the `turn.complete` retry writes, with `label: request`). In `finally`: `isRequesting = false` and `cooldown = config.cooldownTurns` (so the proactive trigger does not shake again on the next measurement). In every outcome the hook ends with `return next(e)` exactly once: the keystroke is never swallowed, and an exception from `$.clock.now()` or from the usage write is caught, logged and does not stop it. Never log the draft text.

  The failure usage event in `turn.complete` (`hooks/register.ts:328` to `353`: the `catch` body that logs, sets `stats.last` and writes the event) is the same event with `label: request`; share only the **event data**: add a top-level pure function in `hooks/register.ts`, `failedCompactionEvent(label, context)`, returning the `Omit<UsageEvent, 'version' | 'at' | 'sessionId'>` literal the retry writes today (`event: 'shake'`, `outcome: 'failed'`, `reason: 'compaction failed'`, zero counts, empty `artifactIds`, `adviseTokens: null`, the given `label` and the `contextTokens` / `contextPercent` of `context`), and have both call sites pass it to `writeUsageEvent` with their own operations literal. The `turn.complete` retry behavior is unchanged.
- **D5. The Shake itself.** In the `session.compact` hook the settings line (`hooks/register.ts:451` to `452`) becomes: `aggressive` keeps `{ ...config, protectTokens: config.aggressiveProtectTokens }`; `idle` uses `{ ...config, minSavings: 0 }`; otherwise `config`. Nothing else in that hook changes: stats, the one-time pass hint, the `shook` log line, `markedSkip` and the usage event all already key on `request`, so an idle pass counts as a pass, carries `label: 'idle'` and uses the existing skip reasons (`nothing worth shaking` when nothing is eligible at all, since `minSavings` 0 only removes the savings check at `hooks/shake.ts:141`).
- **D6. Status.** `statusText` gets one new line directly after the `advice:` line: `idle shake: after {idleShakeMinutes} min idle, 0 = off`. The `options:` line counts `CONFIG_OPTION_NAMES` and therefore reads `14 default` where it read `13`.
- **D7. Plugin manifest and README.** `.claude-plugin/plugin.json` gets an `idleShakeMinutes` option entry in the existing style (title `Idle Shake minutes`, description `Minutes of idle time after which the next prompt first requests an idle Shake; zero disables it.`, `"required": false`). The README options table gets the row `| \`idleShakeMinutes\` | \`0\` | Minutes idle before the first prompt back requests an idle Shake (the prompt cache is cold by then); \`0\` disables it. |`, placed after the `adviseTokens` row. No other README text.
- **D9. Loader rule for `$` (verified).** The `claude` 2.1.295 hooks-module loader refuses a module in which `$` itself is passed to anything other than a function declared at the top level of the file (a function declaration, or a `const` bound to one) or imported from the module's own files; it also refuses `$` returned, spread, bound or read as a value. Using it as `$.noun.event(...)` inside any nested function or arrow is allowed (the file already does this, e.g. `now: () => $.clock.now()`). So: no function local to `register()` may take `$`; pass members (`$.clock.now()` results, `(text) => $.ui.log(text)`, `$.fs.write` wrappers) or declare the arrow where `$` is in scope. `AGENTS.md` says the same ("I/O modules take the `$` member they need as a parameter"). The developer checks the loader at the first `claude plugin test .` run after the edit; a loader refusal prints the rule.
- **D8. Honesty and invariants.** No product invariant changes: the pass is a request (a failure or a skip leaves the transcript untouched), artifacts are committed before placeholders, no tool body is logged. The idle pass is labeled `idle` in the usage log so a later report can separate it.

## 4. Out of scope

Persisting the last-turn time so a resumed session can idle-shake (backlog B28); letting the idle pass serve a queued `/shake` or a `wanted` retry; per-model or per-plan TTL; a toast; a report line for idle passes (labels already separate them in the usage log); a context-floor option; changing the default of `idleShakeMinutes`; any change to `shake.ts` selection; queueing a rejected idle request for turn end (a shake after the turn has warmed the cache pays the invalidation `minSavings` guards, so a rejection is dropped); a `prompt.submit` hook or a timer (sections 1 and 7); idle shaking when the prompt is submitted without any edit event (a remote or SDK client, a replayed draft) is not covered, only a typed or pasted edit.
